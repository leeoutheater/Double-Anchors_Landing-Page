# 11. 극장 매개 · 공간 추천 (Theater Brokering & Space Recommendation)

문서버전: Draft v0.1 · 작성기준일: 2026-06-01

> 공연자↔가상극장의 **매개(broker)** 기능 설계. [06] '예술가↔극장' 흐름을 구현으로
> 구체화한다. 전국 극장 데이터를 보유한 가상극장이, 공연자의 작품 요구에 **최적의
> 물리적 공간을 제시**한다. 개념: [00][07], 운영: [10], 기존자산: [08].

---

## 1. 매개 모델 (Brokering Model)

```
 공연자 ──[작품 컨셉·계획안·공간 요구]──▶ 가상극장(전국 극장 DB 보유)
        ◀──[최적 물리공간 제시 + 근거 + 대안 + 리스크]──
        ──[가상시연으로 후보 공간에 작품을 얹어 검증]──▶ 극장과 협의·대관
```

- 공연자는 "이런 공연을 하고 싶다"(컨셉·형식·규모·기술요구)를 제출.
- 가상극장은 보유한 **전국 극장 디지털 트윈/사양 DB**에서 요구를 가장 잘 구현할
  공간을 **순위·근거와 함께** 제시.
- 제시된 후보 공간에 작품을 **가상시연**으로 얹어 구현가능성·안전성·사이트라인을
  실제로 확인([00] 검증 4축) → 극장과 대관 협의([10] 운영).

## 2. 입력 — 작품 요구 프로파일 (Requirement Profile)

공연자가 제출하는 구조화된 요구. (자유서술 → AI 보조로 구조화)

| 범주 | 항목 |
|------|------|
| 공연형식 | 프로시니엄/돌출/원형/가로지름/양면/블랙박스/환경·이머시브/사용자정의 |
| 규모 | 목표 객석 수, 출연 규모, 공연 길이·횟수 |
| 무대 요구 | 무대 치수(W×D×H), 무대전환, 트랩·승강, 특수 바닥 |
| 기술 요구 | 조명(채널·포지션), 음향(배치·SPL), 영상(프로젝션/LED), 무대기계, **리깅 하중** |
| 안전·특수 | 특수효과(파이로)·화재, 군중·동선, 비상 |
| 제약 | 예산, 지역, 일정, 접근성(배리어프리) 요구 |

## 3. 전국 극장 데이터베이스 (Korea-wide Theater DB)

### 3.1 데이터 항목 (극장 디지털 트윈 L0 스키마 확장)

위치·운영주체 / 객석(규모·배치·**사이트라인**) / 무대형식·가변성 /
프로시니엄·무대 치수(W×D×H) / **그리드 높이·플라이(바텐 수·간격·하중)** /
윙·백스테이지 / 구조 하중·무주(無柱) 스팬 / 전기·디머·무대전원 / 음향 특성 /
get-in(반입구·하역) / 대관 정책·요금 / 접근성 / **무대시설 안전등록** 상태.

### 3.2 데이터 소스 (한국 — 검증 필요, → D19)

- **공연예술통합전산망(KOPIS, kopis.or.kr)** — 공연시설·공연장 정보 / Open API
- **공공데이터포털(data.go.kr)** — 전국 공연장 현황 데이터셋
- **문화체육관광부** — 「공연법」 등록 공연장 현황
- **(사)한국문화예술회관연합회** — 전국 문예회관
- **무대시설 안전** — 「공연법」 무대시설 안전진단 대상 정보
- **시드(seed):** 의뢰자 보유 정밀 모델(LEEOU_THEATER 6형식, 아츠칼리지) + 실측 트윈

> 공공 데이터는 *행정·메타* 수준이 대부분이므로, **정밀 트윈(치수·하중·사이트라인)**
> 은 도면·실측(.e57 점군)으로 단계적 정합·보강한다. [08] 트윈 표준화와 연동.

## 4. 매칭 · 추천 엔진 (Matching Engine)

```
요구 프로파일 정규화
  └─▶ ① 하드 제약 필터 (무대 치수·리깅 하중·형식 수용·안전 충족 여부)
        └─▶ ② 소프트 스코어 (사이트라인·규모 적합·예산·지역·일정·접근성 가중합)
              └─▶ ③ 랭킹 + 근거 설명 + 대안 + 미충족·리스크 명시
```

- **가변형식 극장**은 형식 변환 가능성을 반영(메타극장 형식 생성기 연계 — [07]).
- 결과는 "최적 공간 1 + 대안 N + 각 공간의 충족/미충족/리스크"로 제시(설명가능).
- 가중치는 정책·공연 성격에 따라 조정 가능(→ D20).

## 5. 매개 워크플로우 (End-to-end)

1. 공연자: 컨셉·계획안·요구 프로파일 제출
2. 엔진: 전국 극장 DB 매칭 → 최적 공간 추천(근거 포함)
3. 공연자/극장: 후보 트윈에 작품을 **가상시연**으로 얹어 검증([00] 4축)
4. 극장: 구현가능성·안전성 확인 → 대관·일정 협의([10] 운영)
5. 공론/공공: 필요 시 공론의 장·지원심사로 연계([07][10])


## 8. 화면 / 뷰 (Role-based)

- **공연자:** 요구 입력(자유서술+구조화) → 추천 결과(공간 카드·근거·리스크) → 가상시연 연결
- **극장운영자:** 자기 극장 트윈·사양 등록·갱신, 매칭 수신·대관 협의
- **공공기관:** 지역·정책 기준 매칭 통계, 공간 활용·접근성 지표

## 10. MVP / 미결 (→ DECISIONS)

- **MVP:** 시드 극장(보유 모델 + 소수 협력 극장 트윈) 대상으로 요구→하드필터→
  랭킹→근거 제시 + 가상시연 연결.
- **D19** 전국 극장 데이터 소스·수집 방식(KOPIS API/공공데이터/제휴)
- **D20** 매칭 가중치 정책(작품성 우선 vs 안전 우선 vs 예산 우선)
- **D8(기존)** 대관·정산 연동 범위

## 11. 의뢰자 검수 포인트

1. 요구 프로파일 항목이 실제 공연 기획 관행과 맞는가
2. 매칭 하드제약(치수·하중·안전)·소프트스코어 항목·가중치
3. 전국 극장 데이터의 현실적 확보 경로(공공데이터 한계 vs 실측 제휴)
