### 1.1 8계층 아키텍처 (기존)

| 계층 | 명칭 | 역할 | 상태 |
|------|------|------|------|
| **L0** | 데이터 모델 | 극장/공간/장비 스키마(Zod) | ✅ 완료 |
| **L1** | 웹앱(시뮬레이터) | 입력·3dm 업로드·AI 가상연출 | 🟢 진행 중 |
| **L2** | Reverse Algorithm | GHPython 정적모델→파라메트릭 추출 | 🟡 Edge 프로토타입 |
| **L3** | Grasshopper 처리 | 라이노/GH 연출 알고리즘·Marionette | 🟡 학습 중 |
| **L4** | TouchDesigner | 실시간 미디어 처리 | 🔵 브리지 참조 |
| **L5** | Unreal/Blueprint | 실시간 렌더링·VR | ⚪ 미착수 |
| **L6** | MVR/GDTF 출력 | 산업표준 조명 데이터 | ⚪ 설계 |
| **L7** | 운영 통합 | 극장 운영 워크플로우 | ⚪ 미착수 |

### 1.2 핵심 산출물

1. **L1 standalone HTML** (~5,000줄, 단일 파일): rhino3dm@8.17(WASM) + three@0.160 +
   OrbitControls. `.3dm/.dwg/.skp` 업로드, Brep→Mesh 5전략, 뷰포트 프리셋,
   **극장기준점·절대좌표**, OSnap, IndexedDB 세션, PWA, 크로스플랫폼(Win/Mac/Android/iOS).
   AI 4종(Claude/Gemini/LM Studio/AnythingLLM).
2. **Reverse Algorithm** (GHPython, Phase-3-Edge): Vertex/Edge/Face 제어 + 역산.
   GHPython 절대규칙 4가지.
3. **L1 Next.js 트랙**: TypeScript + Next.js 15 + React Three Fiber (병렬 트랙).
4. **GDTF 도구군**(legacy): GDTF 다운로드/변형/검증(DIN SPEC 15800:2022-02), MVR,
   xml-to-GDTF 빌더.
5. **지형→Unreal 하이트맵**: AWS Terrain Tiles → 16bit PNG/RAW → Unreal Landscape.
6. **PDF 인덱서**: FastAPI + LM Studio 멀티검색.

## 2. 수렴점 — 기존 철학과 본 기획안은 같은 곳을 본다

| 본 기획안 개념 | 기존 자산의 대응 | 통합 효과 |
|----------------|------------------|-----------|
| 가상시연(실연 전 검증) | "과정 그 자체를 가상화·자료화" | **동일 철학** — 개념적 정당화 완성 |
| 개방형 과정 관극([07]) | "과정의 자료화" | 자료화→시민 향유로 확장 |
| 구현가능성×안전성([00]) | **Braceworks**(리깅·구조), 실측·허용오차 검증기 | 안전 검증의 **구체적 엔진** 확보 |
| 극장 디지털 트윈([03]) | 극장기준점·절대좌표·실측(.e57)·Zod 스키마(L0) | 트윈 데이터 모델 **이미 착수됨** |
| 블랙박스 메타극장([07]) | 가변 무대형식 + 사용자 정의 공간 | 메타공간으로 일반화 |
| 조명·기술 표준 | MVR/GDTF·USITT 큐시트·grandMA3·DMX/sACN | 산업 호환성 **이미 확보** |
| 4주체 권한([06]) | 무대감독·디자이너 동일권한(RBAC) 요구 | RBAC 설계 **이미 요구됨** |

> 결론: 기존 자산은 본 기획안의 **'제작·검증 엔진'을 이미 구축 중**이었다.
> 본 기획안은 그 위에 **개념(4주체·생애주기·공공성)과 운영·향유 계층**을 얹는다.

## 3. 통합 매핑 — 8계층 ↔ 본 기획안

```
 [본 기획안]                          [기존 8계층]
 기획(작품성·예산) ─────────────────  (신규) ← 본 기획안이 보강
 가상시연 엔진 ────────────────────  L1 웹앱 + L2 Reverse + L3 GH
 극장 디지털 트윈 ─────────────────  L0 데이터모델 + 극장기준점 + 실측
 구현가능성·안전성 ───────────────  Braceworks + 허용오차 + L6 MVR/GDTF
 실시간 미디어·렌더 ──────────────  L4 TouchDesigner + L5 Unreal/VR
 운영(시즌·대관·정산) ─────────────  L7 운영 통합 (미착수) ← 본 기획안이 확장
 공론의 장·시연홍보·과정관극 ──────  (신규) ← 본 기획안이 신설
 향유(시민·접근성) ───────────────  (신규) ← 본 기획안이 신설
```

## 5. 기술 스택 정합 — 본 기획안 [03] 갱신 지침

본 기획안 [03-기술아키텍처]의 *일반적 후보 스택(WebGPU/Three.js 등)* 은 기존
자산의 **구체적·산업표준 스택으로 대체·구체화**한다.

- **모델링/파라메트릭:** Rhino(.3dm)+Grasshopper(GHPython)+Hops/Rhino Compute
  (입력 호환: .dwg/.skp → GH 단일화)
- **웹 시연:** Three.js + rhino3dm(WASM), Next.js+R3F(프로덕션 트랙)
- **2D 도면·페이퍼워크:** Vectorworks(Datalink·Spotlight) + **음향·영상·소품·의상
  페이퍼워크 도구 확장**(NOTE 요구)
- **안전:** **Braceworks**(리깅·구조 하중) + 허용오차 검증기 + 실측(.e57 점군)
- **조명·쇼컨트롤:** grandMA3, **MVR/GDTF(DIN SPEC 15800)**, DMX/sACN, USITT 큐시트→QLab/MA3
- **미디어/렌더:** TouchDesigner(NDI), Unreal Engine 5(VR), Master Clock 동기화
- **시간 동기:** 지터(jitter) ≤ 16ms — *현장 용어로 재서술 필요*(NOTE 요구)

## 6. 통합 실행 순서 (Integration Sequence)

1. **안정화(FIX):** L1의 Brep→Mesh·임포트·실행 오류부터 해소(현재 진행 계층)
2. **개념 재배치(REVISE):** 8계층을 4주체·생애주기 뷰로 매핑(본 문서 §3 기준)
3. **트윈 표준화(KEEP+):** L0 Zod 스키마 + 극장기준점 + 실측을 디지털 트윈 표준으로 정식화
4. **안전 통합:** Braceworks·허용오차·실측을 [00] '구현가능성×안전성' 검증으로 편입
5. **신설(NEW):** 공론의 장·시연홍보·과정관극·시민향유를 L7 위 신규 계층으로 추가
6. **운영조직(L7):** 상주단체·시즌·권한·정산 워크플로우 구축

## 7. 경계·주의 (Boundaries)

- **아단(Adan) 연관 제외:** 드라이브 내 `안면도_Theater_Adan` 지형 등 아단 종속
  자산은 의뢰자 지침에 따라 **본 기획안에 연관시키지 않는다**. 지형 임포트 등은
  프로젝트 무관한 *일반 기능*으로만 추상화해 계승한다.
- **legacy 폴더:** `..._설계_legacy`는 참조용 보관. 현행은 `가상공연제작_플랫폼/`.
- **권한·키 보안:** standalone HTML의 브라우저 직접 AI 호출(localStorage 키)은
  공유 시 노출 위험 — 프로덕션은 서버측(Edge Function) 경유로 전환.
