# 13. 공연자 기능 설계 (Performer Functions & Experience)

문서버전: Draft v0.1 · 작성기준일: 2026-06-01 · 극장장 제안 → 의뢰자 방향 반영

> 이 문서는 [07]·[10]의 '공론의 장'을 **공개·대중 참여·과정 중심 평가**로 **재정의**
> 한다(의뢰자 방향). 공연자에게 이 가상극장은 *심사받는 곳*이 아니라 **상상을 펼치고
> 구현 방법을 찾는 창작의 집**이다. 개념: [00], 운영: [10], 매개: [11].

---

## 0. 전제 — 공연자에게 이 극장의 의미

1. **1차 목적:** 자기 상상을 가상으로 온전히 표현하고, **실제로 구현 가능한 구체적
   방법을 찾는 것**. (지원금 획득은 부차적 결과이지 목적이 아니다)
2. **평가의 무게중심:** 소수 심사위원 → **관객의 호응·관심·평가**. 작품성과 **대중성**을
   함께, 공정하게.
3. **과정 중심:** 결과물뿐 아니라 **"어떻게 만들어지는가"(제작 과정)** 도 평가·향유의
   대상. (기존 VPP 철학 "과정의 가상화·자료화"와 정확히 일치 — [08])
4. **참여로 유지:** 공연자는 손님이 아니라 **상주 예술가이자 기여자**. 협업하고,
   서로 평가하고, 관객을 데려온다.

## 1. 공연자 범주 & 상주 모델 (Residency)

### 1.1 범주
- **개인 예술가 + 단체(극단·컴퍼니)** 모두
- **전국 + 해외**까지 (→ 다국어·시차·해외 결제 고려, D)

### 1.2 월별 상주 선정 (Monthly Residency)
- **매월 신청** → **공연자 프로필·계획 공개** → **관객(시민)이 상주 여부를 결정**
  (소수 심사 아님 — 시민 주권. [14] 거버넌스)
- **선정 방식(확정):** **2라운드 투표** — ①1차(1개월, 시민 단독, 심사위원 배제) →
  ②2차(심사위원 가점 + 재투표) → **최종 5개 작품 = 그 달의 상주**. 상세: [16].
- **사용료:** 작품 특성·최종 순위에 따라 **전액 무료 ~ 최대 50% 감액** (매핑 = D23)
- **재원:** 무료/50% 지원의 바탕은 **시민 기부**(핵심) + 공공 매칭펀드 — [05][14]

## 2. 레퍼런스 = 매뉴얼 (의뢰자 창작 공연)

- **의뢰자가 직접 창작한 공연**을 *레퍼런스 사례*로 삼아 "이렇게 가상극장을
  이용한다"를 보여주는 **따라하기형 매뉴얼/튜토리얼**.
- 온보딩에 내장: 대본→가상시연→라이브 시연 전 과정을 레퍼런스로 시연.
- 기존 VPP NOTE의 "단계별 학습 툴 연동" 요구와 결합.
- 자산 연결: 의뢰자 지정 예정(드라이브에서 식별·등록) (→ D24)

## 3. 창작 파이프라인 — 대본 → 가상시연 → 라이브 시연

공연자 작업의 중심 축. 세 단계가 하나로 이어진다.

### 3.1 대본 / 공연텍스트 창작 (Script → Performance Text)
- 대본·희곡·시놉시스 작성 공간
- **지시문(비언어·음향·시각 기호) → 공연텍스트 → 큐 변환** (USITT 큐시트 연계 —
  기존 NOTE의 "시놉시스→USITT 큐시트 JSON" 및 Drive 텍스트연구와 연결)
- 협업 집필·버전 관리

### 3.2 가상시연 (Virtual Pre-visualization)
- 무대·동선·조명·음향·영상·큐를 시간축에 구성(L1 에디터)
- 극장 트윈 적용([11] 추천 공간), 검증 4축([00]): 작품성×대중성·구현·안전·예산
- **상상 우선:** 블랙박스 메타극장으로 *어떤 형식·상상도* 먼저 펼치고 → 구현가능성
  탐색

### 3.3 라이브 시연 (Live Showing)
- 실시간 시연·리허설 송출(WebRTC), **관객 라이브 참관**
- 라이브 큐 운용(오퍼레이터 콘솔), 관객 실시간 호응 수집

## 4. 공개 평가 모델 (Open Evaluation) — 핵심 재정의

> 소수 심사 → **공개·대중 참여·이중축·과정 포함** 평가.

### 4.1 관객 우선 신호
- **관심(interest)** · **호응(engagement, 과정관극·라이브 중)** · **평가(rating·코멘트)**
- 관객 반응이 공연자에게 가장 먼저·크게 전달되는 1차 피드백

### 4.2 이중축 — 작품성 × 대중성, 둘 다 공정하게
- **작품성:** 동료·전문가 평가(루브릭)
- **대중성:** 관객·대중 평가(공개 참여)
- 두 축을 **투명하게 병행·집계**(가중·표시 방식 = 의뢰자 확정, D25). 어느 한쪽이
  숨겨지거나 독점하지 않음.

### 4.3 과정 중심 평가 (Process-centric)
- 기록된 **제작 과정**(대본~라이브)을 바탕으로 *어떻게 만들어졌는가*를 평가
- 결과만이 아닌 **여정**을 인정 → 실험·도전 보호 (Drive '청소년 창작극 과정연구'와 결)

### 4.4 공모 평가의 민주화
- 공연자가 문화예술 공모사업에 지원할 때도, 소수 심사 위임을 넘어 **공개·대중
  참여 평가**로 작품성·대중성을 함께 공정하게. 공론의 장 = 그 공개 평가의 광장.
- 평가 기록은 공개·추적 가능(책무성, [10] L9).

## 5. 협업 (Collaboration)

- **공연자 간 공동창작**(개인↔개인, 단체↔개인, 국내↔해외)
- 디자이너·기술 협업(조명/음향/영상/무대 동일권한), 원격 리허설
- **모든 협업 과정 자동 기록** → 과정 평가·아카이브의 원천

## 6. 과정 기록 · 아카이브 (Process Record)

- 대본부터 라이브까지 **전 과정 자동 기록·자료화**
- 용도: ① 과정 중심 평가 ② 시민 개방형 과정관극([10]) ③ 교육·매뉴얼 ④ 다음 작품 환류
- 공개도 단계 설정(비공개/관계자/시민공개)

## 7. 관객 연결 (공연자 관점)

- **연습 과정부터 관객을 모은다** — 시연 기반 홍보, 과정 공개
- 관객 호응이 곧 평가이자 창작 동력
- 공연자가 **자기 관객을 소유·축적** → 다음 작품으로 이어지는 플라이휠

## 8. 데이터 모델 (공연자 관련 엔티티)

```
Performer { type: 개인|단체, region: 국내|해외, profile, portfolio }
ResidencyApplication (월별 신청) ──< ResidencyDecision (무료|50%, 사유)
ReferenceWork (의뢰자 창작 공연 — 매뉴얼 사례)
Script / PerformanceText ──> CueSheet (지시문→큐)
Production ──< PrevizSession / LiveShowing
Collaboration (공동창작·역할)
ProcessRecord (대본~라이브 전 과정 로그)
Evaluation { audience(관심·호응·평가), peer(작품성), process(과정) }
AudienceRelation (공연자↔관객 축적)
```

## 9. MVP — 최소 공연자 경험 (refined)

> "공연자가 대본/구상을 가상시연으로 펼쳐 트윈에 얹고, 과정을 공개해 **관객의
> 관심·호응·평가**를 받으며, 구현 방법을 구체화한다."

포함: 대본/컨셉 입력 → 가상시연 에디터 → 트윈 적용·기초 검증 → 과정 공개(관극) →
관객 관심·평가 수집 → 월별 상주 신청 → 레퍼런스 따라하기 온보딩.
제외(후속): 라이브 송출 정밀화, 해외 결제, 공모 연계 자동화.

## 10. 미결 / 의사결정 (→ DECISIONS)

- **D23** 월별 상주 선정·요금(무료/50%) 기준 — 작품 특성 정의 / 관객참여 반영 여부
- **D24** 레퍼런스로 쓸 의뢰자 창작 공연 지정·자산 연결
- **D25** 이중축(작품성·대중성) 평가 집계·가중·표시 방식
- **D26** 과정 중심 평가의 항목·루브릭
- **D27** 해외 공연자 지원 범위(다국어·시차·결제)

## 11. 의뢰자 검수 / 입력 필요

1. 레퍼런스로 삼을 **본인 창작 공연**(제목·위치) — 매뉴얼 사례로 등록
2. **상주 선정·요금 기준**(작품 특성 → 무료/50% 판정)
3. **평가 모델 구체**: 관객·전문 비중, 과정 평가 루브릭, 공개 수위
4. 대본→큐 변환에서 반영할 **희곡 지시문 체계**(의뢰자 텍스트연구 자산 연계)
