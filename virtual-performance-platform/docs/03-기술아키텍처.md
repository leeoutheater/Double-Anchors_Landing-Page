# 03. 기술 아키텍처 — 가상공연제작 웹플랫폼

문서버전: Draft v0.1 · 본 문서는 **검토용 제안**이며 확정 전 PoC로 검증한다.

## 1. 아키텍처 원칙 (Principles)

1. **Web-first**: 핵심 제작·관람 경험은 무설치 웹에서 동작.
2. **하이브리드 렌더링**: 가벼운 편집은 클라이언트, 고품질 출력은 서버 렌더.
3. **모듈화**: 무대/아바타/음향/송출/수익화를 독립 서비스로 분리해 확장.
4. **비용 인지 설계**: 실시간 인프라는 사용량 기반, 사전렌더 우선.
5. **국제화 내장**: 데이터·UI 모두 i18n 전제.

## 3. 기술 스택 후보 (Candidate Stack)

> 확정 아님 — PoC 결과로 교체 가능. 팀 역량/비용 기준 재검토.

| 레이어 | 후보 | 비고 |
|--------|------|------|
| 프론트(스튜디오) | TypeScript + React/Svelte, Three.js/WebGPU | 무설치 3D 편집 |
| 실시간 협업 | CRDT(Yjs 등) + WebSocket | 공동편집/버전 |
| 라이브 송출 | WebRTC SFU(예: mediasoup) + RTMP 브리지 | 저지연·외부 동시송출 |
| 백엔드 | Node.js/TS 또는 Go (서비스별) | 모듈형 |
| 데이터 | PostgreSQL(메타) + 오브젝트 스토리지(에셋) + Redis(세션/큐) | |
| 렌더 파이프라인 | 서버 GPU 렌더(사전렌더), FFmpeg 트랜스코딩 | 고품질 출력 |
| AI | 외부 API 우선 → 핵심 기능 내재화 검토 | 비용/품질 검증 |
| 배포 | 컨테이너 + 오토스케일, CDN | 사용량 대응 |
| 결제 | PG 연동(국내/글로벌) | 자체 결제망 비범위 |

## 4. 렌더링 전략 (핵심 의사결정)

가상공연의 품질·비용 핵심은 "어디서 렌더하느냐"이다.

| 모드 | 방식 | 장점 | 단점 |
|------|------|------|------|
| **클라이언트 렌더** | 브라우저 WebGPU | 인프라 비용↓, 인터랙티브 | 디바이스 편차, 품질 한계 |
| **서버 렌더(사전)** | GPU 서버 렌더→영상 | 고품질, 균일 | 즉시성↓, 비용 |
| **하이브리드(권장)** | 편집·리허설=클라이언트, 본 공연=서버렌더/스트리밍 | 균형 | 구현 복잡도 |

→ **초기 전략:** 하이브리드. MVP는 클라이언트 렌더 + 사전녹화 발행 중심,
라이브 저지연은 다음 단계에서 SFU로 확장.

## 5. 데이터 모델 (핵심 엔티티 초안)

```
User ──< Membership >── Team
Team ──< Project
Project ──< Scene (무대 구성: 카메라/조명/레이어)
Project ──< Performer (아바타·모션·의상)
Project ──< AudioTrack (음원·큐마커)
Project ──< CueSheet (타임라인 큐: 조명/카메라/이펙트)
Project ──< Broadcast (라이브/사전녹화, 상태)
Broadcast ──< Ticket / Donation / Viewer
Project ──< Archive (VOD, 자막, 챕터)
Asset (무대/아바타/음원/이펙트, 라이선스 메타) ──< 프로젝트 참조
```

## 6. 핵심 기술 리스크 & PoC 항목

| 리스크 | 검증할 PoC |
|--------|-----------|
| 브라우저 3D 성능 | 표준 노트북에서 다중 아바타+이펙트 30fps 가능한가 |
| 라이브 저지연 | SFU 경유 글로벌 관객 지연/품질 측정 |
| AI 모션 추출 품질 | 영상→아바타 모션 자연스러움/비용 |
| 렌더 비용 | 사전렌더 1공연당 GPU·트랜스코딩 단가 |
| 동시 관객 부하 | N명 동접 스트리밍 안정성 |

## 7. 단계별 기술 확장

- **Phase 0–1:** 클라이언트 렌더 + 사전녹화, 단순 관람+채팅, PG 연동
- **Phase 2:** 라이브 저지연(SFU), AI 무대생성/자막, 실시간 협업
- **Phase 3:** 서버 고품질 렌더, 영상→모션, 외부 동시송출, 에셋 마켓

## 8. 보안/컴플라이언스

- RBAC, 프로젝트 격리, 서명된 미디어 URL
- 저작권/초상권: 라이선스 메타데이터, 업로드 동의 절차
- 개인정보·결제: 관련 법규/PG 보안표준 준수(상세는 별도 정책 문서화)
