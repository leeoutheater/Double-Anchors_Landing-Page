## 0. 채택 아키텍처 — 기존 8계층 + 본 기획안 확장 계층

기존 VPP의 8계층(L0~L7)을 채택하고, 본 기획안의 개념 계층을 그 위에 얹는다.

| 계층 | 명칭 | 기술 | 본 기획안 매핑 |
|------|------|------|----------------|
| L0 | 데이터 모델 | Zod 스키마(극장/공간/장비) | 극장 디지털 트윈 기반 |
| L1 | 웹앱(시연 시뮬레이터) | Three.js + rhino3dm(WASM), Next.js+R3F | 가상시연 에디터 |
| L2 | Reverse Algorithm | GHPython(Vertex/Edge/Face 역산) | 직관 편집→파라메트릭 |
| L3 | Grasshopper 처리 | GH + Hops + Marionette | 연출·구성 알고리즘 |
| L4 | TouchDesigner | 실시간 미디어(NDI) | 영상·미디어 |
| L5 | Unreal/Blueprint | UE5 + VR | 고품질 렌더·몰입 |
| L6 | MVR/GDTF 출력 | DIN SPEC 15800, DMX/sACN, USITT 큐시트 | 조명·쇼컨트롤 표준 |
| L7 | 운영 통합 | (미착수) | **운영조직 모델([07])** |
| **L8+** | **공론·홍보·향유** | (신규) | **공론의 장·시연홍보·과정관극·시민향유** |
| **L9+** | **공공·책무성** | (신규) | **예산·심사·성과·접근성** |

- **안전성 엔진:** Vectorworks **Braceworks**(리깅·구조 하중) + 허용오차 검증기 +
  실측(Disto·점군 .e57/.pts/.csv) + 신뢰도맵 → [00] '구현가능성×안전성' 구현부.
- **클라우드:** **Rhino Compute**(헤드리스 리버스 알고리즘 상시 가동) + 웹 3D 뷰어.
- **시간 동기:** Master Clock, 지터(jitter) ≤ 16ms *(현장 용어 재서술 예정)*.

## 1. 아키텍처 원칙 (Principles)

1. **단일 데이터 / 다중 뷰:** 하나의 시연본을 4주체가 역할별 뷰로 본다.
2. **현장 정합성:** 극장 디지털 트윈은 실제 규격·안전기준 데이터를 따른다.
3. **하이브리드 렌더링:** 가벼운 시연은 클라이언트, 고품질·정밀 시뮬은 서버.
4. **검증 추적성:** 모든 검증·예산·의사결정 이력을 기록(공공 책무성).
5. **개방형 표준:** 무대·극장 데이터는 표준 포맷(glTF/IFC 등) 우선.

## 3. 핵심 서브시스템

### 3.1 가상시연 엔진 (Pre-visualization Engine)
- 씬 그래프: 무대·세트·조명·음향·영상·출연·동선을 시간축(큐시트)에 배치
- 렌더: WebGPU 우선, WebGL 폴백 / 고품질은 서버 렌더
- 협업: CRDT 기반 동시 편집, 버전 스냅샷·롤백

### 3.2 극장 디지털 트윈 (Theater Digital Twin)
- **데이터 모델:** 무대 치수, 프로시니엄, 윙/백스테이지, 그리드 높이,
  플라이시스템(바텐 수·위치·하중 한계), 객석 배치·사이트라인, 음향 특성,
  전기·디머·리깅 포인트, 출입·동선·비상동선
- **포맷:** 건축은 IFC/BIM 참조, 시각화는 glTF/GLB, 좌석·사이트라인은 자체 스키마
- **확보:** 파일럿 협력 극장 실측/도면 → 표준 스키마로 정규화

### 3.3 시뮬레이션 엔진 (Validation/Simulation)
- **구현가능성:** 무대전환 시퀀스·전환 시간, 장비 사양 적합성, 충돌·간섭 체크
- **안전성:** 플라이·리깅 하중 합산·한계 경고, 구조 하중, 동선·군중·비상동선,
  특수효과(파이로)·화재 안전구역
- **사이트라인:** 좌석별 가시선·차폐 계산(시민 향유 뷰와 공유)
- ⚠️ **책임 경계:** 의사결정 보조용. 공식 구조·안전 인증을 대체하지 않으며
  결과에 면책·전문가 검토 안내를 명시한다. ([DECISIONS] 책임범위 확정 필요)

### 3.4 예산·성과·책무성 (Budget/Accountability)
- 시연 구성요소 → 자원 산정 → 예산 항목 매핑(규칙 기반)
- 시나리오 비교, 지원 심사·집행·성과 추적, 감사 가능한 변경 이력

### 3.5 향유·송출 (Audience/Broadcast)
- 무설치 향유 뷰어, 좌석 시야 미리보기, 배리어프리 정보
- 사전녹화 발행 우선, 라이브/하이브리드는 단계적(WebRTC SFU)

## 4. 렌더링·시뮬 전략 (핵심 의사결정)

| 작업 | 위치 | 이유 |
|------|------|------|
| 편집·리허설 시연 | 클라이언트(WebGPU) | 인터랙티브, 인프라비↓ |
| 정밀 안전/하중 시뮬 | 서버 | 정확도·연산량 |
| 고품질 발행물 | 서버 렌더 | 품질 균일 |
| 시민 향유 재생 | CDN 스트리밍 | 규모·접근성 |

→ **초기 전략:** 하이브리드. MVP는 클라이언트 시연 + 서버 사전렌더 + 규칙
기반 안전 점검부터. 정밀 물리 시뮬은 단계적 고도화.

## 8. 단계별 기술 확장

- **Phase 0–1:** 클라이언트 시연 + 트윈 1~3개관 + 규칙기반 안전점검 + 예산 리포트 + 향유 뷰어
- **Phase 2:** 사이트라인·정밀 시뮬, 라이더 매칭, AI 보조, 라이브/하이브리드
- **Phase 3:** 정밀 물리/구조 시뮬, 실연-시연 보정, 트윈/에셋 공유, 다기관 연동
