# 06. 이해관계자 맵 — 4주체 니즈·가치·연결

문서버전: Draft v0.2

> 본 플랫폼은 4주체를 **하나의 디지털 시연본**으로 잇는다. 각 주체의 동기·
> 페인포인트·플랫폼 가치·핵심 기능을 정의한다.

---

## 1. 공연자 (예술가) — Performer / Artist

| 항목 | 내용 |
|------|------|
| **동기** | 작품 구상을 의도대로 무대에 구현하고 싶다 |
| **현재 페인포인트** | 머릿속 구상을 협업자·심사자에게 전달하기 어렵다 / 실제 무대에 올려보기 전엔 검증 불가 / 비용·공간 제약 |
| **플랫폼 가치** | 구상의 즉각적 시각화·시연, 작품성 사전 검증, 원격 협업·리허설, 지원사업용 설득 자료 |
| **핵심 기능** | 무대 시연 에디터, 출연·동선 배치, 큐시트, 협업 리뷰, 시연본 공유 |
| **성공 신호** | "내 작품을 처음으로 남에게 '보여줄' 수 있게 됐다" |

## 2. 극장운영자 (문화재단) — Theater Operator / Cultural Foundation

| 항목 | 내용 |
|------|------|
| **동기** | 우리 극장에 안전하고 적합한 공연을 효율적으로 올리고 싶다 |
| **현재 페인포인트** | 입장 작품이 우리 무대 시스템에 맞는지 사전 판단 어려움 / 안전·하중·동선 검토가 도면·경험에 의존 / 대관·일정·기술 협의가 반복적·비효율 |
| **플랫폼 가치** | 극장 디지털 트윈에 작품을 얹어 **구현가능성·안전성** 사전 검증, 테크니컬 라이더 자동 대조, 대관·일정 사전 조율 |
| **핵심 기능** | 극장 디지털 트윈 라이브러리, 무대기계/플라이/사이트라인 검증, 안전 시뮬레이션, 테크니컬 라이더 매칭, 일정/대관 관리 |
| **성공 신호** | "올리기 전에 우리 극장에서 되는지, 안전한지 안다" |

## 3. 공공기관 (정부) — Public Arts Agency / Government

| 항목 | 내용 |
|------|------|
| **동기** | 한정된 공공 예산을 타당하게 배분하고 성과를 입증해야 한다 |
| **현재 페인포인트** | 지원 심사 시 작품 실체·실현가능성 판단 근거 부족 / 예산 책정의 객관적 기준 부재 / 사후 성과·**책무성** 증빙 어려움 |
| **플랫폼 가치** | 가상시연 기반 심사 자료, 예산 타당성 정량 근거, 사업 진행·성과의 추적·기록, 정책 의사결정 데이터 |
| **핵심 기능** | 사업/지원 대시보드, 예산 시뮬레이션 리포트, 진행·성과 추적, 시민 향유·접근성 지표, 아카이브 |
| **성공 신호** | "왜 이 사업·예산이 타당한지 데이터로 설명 가능" |

## 4. 관객 (시민) — Audience / Citizen

| 항목 | 내용 |
|------|------|
| **동기** | 좋은 공연을 알고, 접근하고, 누리고 싶다 |
| **현재 페인포인트** | 공연 정보가 추상적(텍스트·포스터) / 내게 맞는지(좌석 시야·접근성) 사전 파악 어려움 / 참여·소통 통로 제한 |
| **플랫폼 가치** | 공연 사전 체험, 좌석별 시야·배리어프리 정보, 예매 연계, 하이브리드 관람, 문화 데이터 향유·참여 |
| **핵심 기능** | 시민 향유 뷰어, 사전 체험, 사이트라인 미리보기, 접근성 정보, 예매 연계, 피드백·참여 |
| **성공 신호** | "가기 전에 어떤 공연인지, 내 자리에서 어떻게 보일지 안다" |

## 5. 주체 간 연결 시나리오 (Cross-stakeholder Flows)

| 흐름 | 시나리오 |
|------|----------|
| 예술가 → 공공기관 | 가상시연본을 지원사업에 제출 → 심사자가 실현가능성·예산 타당성 검토 |
| 예술가 ↔ 극장 | 작품을 극장 디지털 트윈에 얹어 구현가능성·안전성 공동 검증 → 대관 확정 |
| 극장 → 공공기관 | 안전·기술 검증 결과를 행정 보고·책무성 자료로 제출 |
| 예술가/극장 → 시민 | 검증된 시연본이 티저·접근성 정보로 전환 → 시민 사전 체험·예매 |
| 시민 → 예술가/공공기관 | 사전 피드백·관심도 데이터가 작품 보완·정책 판단에 환류 |

## 6. 가치 교환 요약 (Value Exchange)

```
        제공(작품·시연본)                검증·승인·예산
 예술가 ───────────────→ 극장/공공기관 ───────────────→ 예술가
   ↑                                                       │
   │ 피드백·관심도                              검증된 향유 자산
   │                                                       ↓
 시민 ←───────────────── 향유·접근·참여 ──────────────── 시민
```

플랫폼은 이 교환의 **신뢰 가능한 단일 매개**가 된다. 같은 시연본을 4주체가
보기 때문에 정보 비대칭과 반복 협의가 줄어든다.

## 7. 권한·역할 설계 함의 (RBAC 시사점)

- 주체별 **뷰가 다르다**: 같은 시연본도 예술가는 창작 뷰, 극장은 기술·안전 뷰,
  공공기관은 예산·성과 뷰, 시민은 향유 뷰로 본다.
- → 기술 설계에서 **단일 데이터 / 다중 뷰(role-based view)** 가 핵심 요구사항.
