# 05. 비즈니스 모델 — 가상공연제작 웹플랫폼

## 1. 수익 모델 (Revenue Streams)

| 모델 | 설명 | 단계 |
|------|------|------|
| **구독(SaaS)** | 제작 기능 등급제(무료/프로/스튜디오) | Phase 1~ |
| **사용량 과금** | 사전렌더·라이브 송출·저장 용량 등 사용분 | Phase 1~ |
| **거래 수수료** | 티켓·후원·VOD 매출의 일정 비율 | Phase 2~ |
| **에셋 마켓** | 무대/아바타/이펙트 거래 중개 수수료 | Phase 3~ |
| **엔터프라이즈** | 기관·브랜드 맞춤(전용 지원·브랜딩) | Phase 2~ |

**핵심 전략:** 제작은 낮은 진입장벽(무료/저가)으로 확보하고,
**송출·관객 규모·수익화 단계**에서 매출을 회수하는 구조.

## 2. 요금제 초안 (Pricing — 가설)

| 플랜 | 대상 | 포함 | 과금 |
|------|------|------|------|
| **Free** | 입문/체험 | 워터마크, 제한 렌더, 1프로젝트 | 무료 |
| **Pro** | 독립 아티스트/소규모 | 사전녹화 발행, 기본 송출, 다중 프로젝트 | 월 구독 |
| **Studio** | 기획사/팀 | 라이브 송출, 협업, 우선 렌더, 분석 | 월 구독(상위) |
| **Enterprise** | 기관/브랜드 | 맞춤·전용지원·SLA | 협의 |

> 구체적 금액은 PoC 비용 산출 + 경쟁/지불의향 조사 후 확정.

## 3. 비용 구조 (Cost Structure)

| 비용 | 성격 | 비고 |
|------|------|------|
| 렌더/GPU 인프라 | 변동(사용량) | 사전렌더·라이브의 최대 변수 |
| 스트리밍/CDN | 변동 | 관객 규모 연동 |
| AI API/모델 | 변동 | 무대생성·자막·모션 |
| 스토리지 | 변동 | 에셋·VOD |
| 인건비 | 고정 | 개발·운영·BD |
| PG 수수료 | 변동 | 거래 매출 연동 |

**원가 관리 핵심:** 변동비(렌더/스트리밍/AI)를 사용량 과금으로 연결해
매출-원가 정합성 유지.

## 4. 단위 경제성 (Unit Economics — 검증 대상)

- 공연 1건당: (구독 분담 + 사용량 + 거래수수료) − (렌더+스트리밍+AI 변동비)
- 목표: 마진 양(+) 구간 도달 가능한 가격·과금 설계
- → Phase 0 PoC에서 **공연 1건당 인프라 단가** 실측 후 가격 역산

## 5. Go-to-Market

1. **베타 커뮤니티**: 1차 타깃(독립 아티스트/소규모 기획자) 초대 베타
2. **레퍼런스 공연**: 눈에 띄는 데모 공연으로 사례 확보
3. **크리에이터 파트너십**: 초기 사용자에게 수익화 인센티브
4. **교육/문화기관 파일럿**: 진로체험·교육형 공연으로 B2B/B2G 진입
5. **다국어 확장**: 자막·UI 다국어로 해외 관객/크리에이터 유입

## 6. KPI 트리

```
북극성 지표: "발행되어 관객이 본 공연 수"
├─ 활성 크리에이터 수
├─ 공연 발행 수 / 크리에이터
├─ 공연당 평균 관객·체류시간
├─ 유료 전환율 (Free→Pro/Studio)
├─ 공연당 평균 수익화 매출 (티켓+후원+VOD)
└─ 공연 1건당 인프라 원가 (마진 관리)
```
